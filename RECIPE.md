# Benni

A Herdr window for running many coding agents across git worktrees. The left sidebar puts the sessions that need you, the ones at work and the ones that just finished on top as tinted cards, then lists every space (optionally split into workspaces such as work and personal, one tab each) with a colored avatar, its repo, branch and ahead/behind, worktrees nested under their main checkout, and each space's agents and terminals beneath it. The tab bar opens a side panel per space: Files, Changes, a full git graph, or the repo's GitHub issues, where one click creates an `issue-N-...` worktree and starts Claude in it with the prompt already typed. A Routines screen schedules Claude Code sessions (cron or presets) that Herdr starts by itself in a background "Routines" space, and keeps their history.

## How it behaves

- **Agent status** reads the same everywhere it shows. Working: a 12px spinner in `working` turning every 900ms. Blocked: a 14px rounded square in `blocked` at `26` alpha with a bold `!` (cards and rows), a `blocked` dot on tabs. Done: a 7px filled dot in `done` (6px on tabs). Idle: a 7px ring (1.5px, `idle`) and `muted` name. On the rail's numbered cells only blocked and done raise a `●`; the rail's session cells show every status mark.
- **PR state color**, wherever a PR shows: `ansi2` open, `dim` draft, `ansi5` merged, `ansi1` closed. Checks glyph while open: `✓` `ansi2`, `✗` `ansi1`, animated `◐◓◑◒` while pending.
- **Cards**: a session gets one the moment it blocks or starts working; once done or idle it moves to "Au repos" and drops off 24 hours after its last change. Cards sort newest change first. Clicking a card or an agent/terminal row focuses that pane (`pane.focus`). Clicking a card's issue line opens the issue on GitHub (tooltip "Ouvrir le ticket sur GitHub").
- **PR lifecycle**, on carded sessions whose own branch is not `main`, `master` or detached:
  - The PR is read with `gh pr list --head <branch>` from the main checkout every 30s while the window is in front (120s otherwise). Moving to a failing CI or to merged posts a notification (click focuses the agent).
  - Step buttons show only while the session rests. "Ouvrir la PR", when there is no PR and the branch has commits past `origin/HEAD`: `git push -u origin <branch>`, then `gh pr create --head` with the ticket title (else the last commit subject) and a body of "Closes #N" and the commit subjects.
  - "Corriger la CI", when an open PR fails: reads `gh run view <run> --log-failed` for each failed Actions run (last 80 lines each, timestamps and colors stripped) and sends the failing checks and logs to the agent with `hc send`; then "Logs de CI envoyés à l'agent" until the PR head changes.
  - "Nettoyer", when merged and the session is in a linked worktree, clicked twice within 4s: refuses uncommitted changes, closes the spaces in that worktree and waits for their terminals, `git worktree remove`, then `git branch -D` if the local branch is the PR head (else `-d`, kept and reported if it holds other commits); the outcome is a notification, as the card is gone.
  - On `main` or `master` instead (read with `git status --porcelain` and `git rev-list --count @{upstream}..HEAD`): "Commit & push (N)" when files changed, which asks the agent with `hc send` to commit them with clear messages and push (then "Commit et push demandés à l'agent" until the next git read), else "Push ↑N" when commits are not on the upstream, which runs `git push`.
  - A step that messages the agent reads "Envoi…", then "En attente de ton brouillon…" if `hc send` has not delivered after 2s (it holds a paste while you type in the session).
  - A carded session's git is read again as soon as its agent changes status.
- A session's issue number comes from its branch `issue-42-...`, else a tab named `#42`, else `#42` in its title; the title is read with `gh api` from the main checkout.
- A Claude session started in a folder that holds `bot.json` shows a bot icon instead of Claude's mark.
- **Spaces**: click selects, right-click opens Herdr's space menu, press and drag onto another space of the same machine reorders (the dragged row fades to 50%, a 2px `accent` line marks the drop). The chevron folds one space's sessions (tooltips "Replier" / "Déplier"); the header button folds or unfolds all ("Tout replier" / "Tout déplier"). Folds are remembered. The `+` runs `space.new`, or with workspaces on makes a space that joins the selected tab (the first new space within 10s).
- **Workspaces**: a click on a tab shows its spaces (remembered); right-click opens the settings. When another space becomes active, from anywhere, the selected tab follows it. Dragging a space onto a tab or the empty slot moves it there, with the worktrees nested under it. Spaces not made from the `+` land in the default workspace. A worktree nested under its main checkout always shows in that checkout's workspace. Agent navigation follows the tabs' order, then the list order; `space.select` indexes and `space.next` keep Herdr's order.
- **Settings**: add (Enter or "Ajouter"), rename (`✎` or double-click, Enter saves, Esc cancels), reorder with `↑`/`↓`, delete with an inline confirmation ("Supprimer « X » ? Ses N spaces iront dans « Default »."). The default workspace (id `default`, "Default") holds every space without one; it can be renamed, not deleted, and is recreated if missing. Clicking a channel card switches the channel and checks again; the cards lock while installing. Esc closes the dialog.
- **Updates**: `benni-spaces` compares the installed commit with the chosen channel's branch on GitHub (`shared("benni.channel")`: `stable` or unset → `main`, `canary` → `canary`) 15s after it starts, then every minute, and stores both in `shared("benni.update")`. When they differ it posts "Nouvelle version du layout", shown 10 seconds, once per new commit (remembered in localStorage `update.notified`); a click runs `mod.open {name: "benni-settings"}`, and the dialog opens on "Mise à jour" while that shared value says an update is pending. A layout installed by hand (no `hc-layout.json`) is never notified.
- The list keeps worktree spaces right under their main checkout by moving spaces itself (`space.move`), and scrolls the active space into view when it changes.
- Git info refreshes when a space changes folder, when a command or an agent's turn ends in that repo, when a machine comes back, when files change in a local repo's git folder, and every 60s for listed repos while the window is in front (six places at a time).
- **Machines**: a header click folds that machine. A machine needing login shows "needs a login: run `hc machine login <name>`" with a Copy button. A machine that was rebuilt shows "Connect", which removes and re-adds it with `hc`. A `⚠` warns that agents stop on disconnect and opens the add-machine dialog.
- **Tabs**: click selects, double-click renames, drag onto another pill moves it, right-click opens Herdr's tab menu, the wheel over the bar steps to the previous or next tab, the cross closes the active tab, `+` opens Herdr's new menu (250 by 512px).
- **Side panel**: a panel button opens that block (or closes the panel if it is already showing). The choice is remembered per space: switching spaces restores that space's panel, or closes it if the space never had one.
- **Issues**: refreshes every 30s while shown and the window is visible, from the focused pane's folder (up to 100 open issues). "Mes issues" keeps only issues assigned to you. On a row, `#N` opens the issue on GitHub and the PR badge opens the PR. Your circle turns `ansi1` with white text on hover (tooltip "Me retirer") and a click unassigns you; the `+` circle assigns you (both show `…` meanwhile). The Claude button launches Claude (tooltip "Lancer Claude"; a braille spinner and "Création du worktree…" while it works), or selects the issue's space when its worktree exists ("Ouvrir la session").
- **Lancer Claude** creates branch `issue-<N>-<slug>` (title without accents, lowercased, at most 40 characters) as a worktree in Herdr's worktree folder (`worktrees.directory`, default `~/.herdr/worktrees`) under `<repo>/<branch>`, based on `origin/HEAD` after fetching it (else `HEAD`), then opens a new space there with tab `#N` running `claude --plugin-dir <claude-draft>` with `CLAUDE_PROMPT_DRAFT="Traite l'issue <url>"`. Claude starts through the user's `$SHELL` (fish: `fish -c`; bash and zsh: interactive `-ic`, so `~/.bashrc` or `~/.zshrc` loads), so a `claude` function or alias there applies; any other shell runs the `claude` binary directly. The small plugin puts that text in Claude's prompt box without sending it.
- **Worktrees à nettoyer**: every linked worktree of the repo (not only `issue-N-...` ones, and whether or not a session card shows) has its PR read with the issues; a merged or closed PR is not asked again until the repo changes. "Nettoyer" or "Nettoyer les N" opens an inline confirmation (border `ansi1` at `55`): "Supprimer le worktree et la branche X ?", the spaces that will close, and in `ansi1` how many agents working or blocked there will stop; "Supprimer" (`ansi1`) or "Annuler". Worktrees go one at a time: `git status --porcelain` again (changes stop that one), `space.close` on each space whose folder or a pane is inside it, a wait of up to 10s for their terminals to end, `git worktree remove` (`git worktree prune` when the folder is gone), then `git branch -D` if the branch still points at the PR head, else `-d`, which keeps a branch holding other commits. A line under the rows reports "N nettoyés · branche gardée, commits absents de la PR : X · échec : Y (why)".
- **Graph**: double-click a branch label to check it out; right-click a commit, label, the uncommitted row or a Manygit repo for git actions (checkout, branch, tag, merge, rebase, cherry-pick, revert, reset soft/mixed/hard, push, pull `--ff-only`, stash, commit, delete). Items ending in `…` ask in a dialog first (danger ones in `ansi1`); every action except fetch first checks that HEAD and the branch have not moved since the menu opened. It follows the focused pane's folder, watches local repos and polls remote ones every 15s.
- **Routines** (`benni-routines`):
  - A routine has a name, description, prompt, schedule, folder, worktree (yes/no), model, effort, `-p` mode (yes/no), enabled, runs kept (default 20), toast at the end, Claude push. Presets become cron: hourly `M * * * *`, daily `M H * * *`, weekdays `M H * * 1-5`, weekly `M H * * D`; "Avancé" takes any 5-field cron (`*`, lists, ranges, steps, day of week 0 or 7 = Sunday; day of month and day of week both restricted means either), local time.
  - The scheduler checks every 15s and starts each enabled routine whose cron matches the current minute, once per minute (`lastFired`). It only runs while Herdr shows this layout. On start it records, per routine, the minutes that fell while Herdr was closed (between the last check and now) as one "Manqué" entry with their count; they are never run late. Turning a routine back on, or saving it, doesn't run the current minute late.
  - A run opens a tab named "<routine> · HH:MM" in the space "Routines" (`space.new {name: "Routines", focus: false}` the first time, then `tab.new {space, focus: false}`): the shown space and tab never change.
  - Claude starts through the user's `$SHELL` like Lancer Claude, with `--session-id <uuid>`, `--model <haiku|sonnet|opus|fable>`, `-n "<routine> · HH:MM"`, and `--effort <level>` unless "Par défaut".
  - Interactive: the prompt is `tab.new`'s `task` (Herdr appends it to `argv`, so Claude gets it as its first message). It ends when the agent turns `done` (or `idle` after working); its summary is the session's last assistant text, read from `<config>/projects/*/<session>.jsonl`. Claude push adds `--remote-control "<routine>"` and asks Claude, at the end of the prompt, to send a PushNotification with a one-line summary under 200 characters.
  - `-p`: `sh run-routine.sh <log> <exit> <args> -p --output-format stream-json --verbose <prompt>`: the raw stream goes to `~/.cache/benni-routines/<run>.jsonl` and the tab shows it readably (`⏺` text, `⏺ Tool(summary)` in grey, "── Terminé en Ns ──" in green or "── Échec … ──" in red, then "Reprendre : claude --resume <id>"); `<run>.exit` gets Claude's exit code. Its summary is the stream's `result`; a nonzero code or an error result makes it "Échec". "Ouvrir" types `claude --resume <id>` in that tab (`hc send`), selects it and closes the screen.
  - Worktree: each run gets branch `routine-<slug>-<AAAAMMJJ-HHMM>` (slug of the name, at most 30 characters; `-2`, `-3` … if taken) under `<worktrees.directory>/<repo>/<branch>`, off `origin/HEAD` after fetching it (else `HEAD`), from the main checkout; Claude starts in the same subfolder of it as the routine's folder. Without worktree it runs in the folder as is.
  - A run whose tab closes before the end is "Échec" ("Onglet fermé avant la fin"); one whose tab never shows within 60s too.
  - With "Toast à la fin", a run's end posts "Routine « X » terminée" (success) or "Routine « X » en échec" (error) with the summary's first line; a click opens the screen on that run.
  - Beyond the routine's kept count, the oldest runs that are not running go: tab closed, entry removed, log files deleted, and the worktree removed with its branch only when it has no uncommitted change and no commit missing from `origin` (`git rev-list --count HEAD --not --remotes=origin`); otherwise it stays and a warning toast "Worktree gardé : <branch>" says why and where.
  - Screen: Esc cancels an inline confirmation, else leaves the editor, else closes the screen, as does the cross. It closes by itself when the window is resized or the sidebar changes width. A click on a routine card filters the history to it (again: all). A click on an interactive run closes the screen and shows its tab ("L'onglet de ce run est fermé." if gone); on a `-p` run it unfolds it. A disabled routine starts neither on schedule nor from "Lancer maintenant". Saving checks a name, a prompt, an existing folder, a git repo when Worktree is on and a valid schedule.
- **Workflow**: while the Claude Code session in the shown tab (the focused pane, else the first Claude pane) runs a workflow, a floating pill at the bottom right of the tab area shows a spinner, the workflow's name and finished/started agents (tooltip "Voir le workflow en cours"); it is read every 4s while the window is visible and disappears when the run ends.
  - A click veils the tab area (black at `a6` alpha, `59` in light themes, a click there closes) and centers on it a card 90% of its width and height: background `popover`, 1px `input` border, 10px corners, a large shadow.
  - Header on `chrome`: name in `accent`, description, "En cours"/"Terminé · N/M agents", a close cross.
  - Left (260px): every phase of the script, done ones `✔` in `ansi2`, running ones with a spinner, not started ones numbered in `dim`, each with its agents (status mark, label, model).
  - Right: the selected agent, live like a Claude Code session: the prompt collapsed in a card, `⏺` assistant text as Markdown, `∴ Réflexion` collapsed, `⏺ Tool(summary)` (spinner until its result, `ansi1` on error) with `⎿` and the first 3 result lines, then the outcome JSON once done.
  - It opens on the newest running agent and follows it until one is picked; a click or ↑/↓ (j/k) picks one; clicking a tool, the prompt or the outcome unfolds it; the transcript keeps to its end while it was scrolled there; 200 events at a time with "Afficher N événements précédents". Esc or the cross closes it, and so does showing another tab or space.

## Watch out

- **Network**: `git-graph` asks `api.github.com/repos/rabeeh-ta/herdr-git-graph/releases/latest` at most once a day (no token); "Stop checking" in its update window, or `CHECK = false` in `update.js`, turns it off. `gh-issues` and `benni-spaces` reach GitHub through `gh`. `benni-spaces` runs `git ls-remote` against github.com/jobenni/hc-layout every minute; `benni-settings` does too when the dialog opens, and "Mettre à jour" clones that repo and runs its `install.sh`.
- **Programs and files**: the mods run `git`, `gh`, `find`, `test`, `sh`, `bash`, `nohup` and `hc` (plus the Linux link opener's programs), on remote machines too. `gh-issues` reads Herdr's `settings.json`, and for a space on another machine writes the plugin to `~/.cache/herdr-gh-issues/claude-draft` there (a local space uses the mod's own `claude-draft/` in place). Graph actions really change repos: reset hard, delete branch, delete remote branch, push.
- **Assumptions**: `gh` installed and logged in. If `mise` exists, `gh` runs under `mise exec` so a folder's `GH_TOKEN` picks the account. Under Linux the mods detect WSL from `/proc/sys/kernel/osrelease`. Claude Code must be on the space's machine for "Lancer Claude". The issue branch convention `issue-<N>-...` links worktrees, sessions and cards.
- **Left out of the repo** because they are generated: `gh-issues/claude-draft/.claude-plugin/types/` (its `tsconfig.json` extends it, so editor type checks fail until it exists) and every mod's `gpui-kit.d.ts` (the `jsconfig.json` files expect one).
- **Language**: the UI is French except "Needs you", "Spaces", "Settings" (the sidebar row) and everything in `git-graph`.
- **Two settings buttons**: the sidebar's "Settings" row opens Herdr's own settings (`app.settings`, with the app update dot); the tab bar's gear "Réglages" opens this layout's `benni-settings` (with the layout update dot). The layout has no native sidebar footer, so without the row Herdr's settings are out of reach.
- **Names are wired into paths**: `tabs-graph` draws `mods/git-graph/icons/graph.svg`, `mods/gh-issues/icons/issue.svg`, `mods/files/file.svg`, `mods/changes/changes.svg`; `benni-spaces` draws `mods/gh-issues/icons/issue.svg` and its own `mods/benni-spaces/*.svg`; `gh-issues` finds its plugin at `<appHome>/mods/gh-issues/claude-draft` and recognises its own block by `mod === "gh-issues"`. Renaming a mod means renaming these.
- **The rail on macOS**: `workspace-chrome` hides its fold button on the macOS rail and expects the agents list to offer the way back. This layout has no agents list and the sidebar is not resizable, so `benni-spaces` must draw its own `»` on the rail; without it the sidebar stays narrow.
- `tabs-graph` lacks what the current shipped `tabs` added since: any wheel event of 1px or more steps one tab (a touchpad swipe skips several), the active tab is not scrolled into view, and a corrupt `panels` entry in its localStorage throws at start.
- `tabs-graph` panel ids are fixed: stack `panel-body`, column `panel`, children `files`, `changes`, `graph`, `issues`. The tab bar's left inset clears the macOS traffic lights from `traffic_lights[0]` and the sidebar width.
- The spaces list reorders spaces by itself; a hand order that splits a worktree from its main checkout is undone.
- Limits: 100 open issues, 3 assignee circles, 300 commits per page in the graph, Manygit depth 1 to 5 (default 3) and at most 500 repos, never scanning a home folder or above.
- **Code repeated across mods**: Herdr refuses imports between mods, so `benni-spaces` and `benni-settings` each carry the same `readWorkspaces` (key, default workspace, unknown ids fall back to `default`) and the same update check (`LAYOUT_REPO`, `CHANNEL_KEY`, `CHANNEL_BRANCHES`, `chosenBranch`, `readInstalledCommit`, `readLatestCommit`, `UPDATE_KEY`). Change both together. Never prune `of` from `spaces()`: spaces of a machine that is loading or offline would lose their workspace.
- The space named `~` gets no stored color (it shows `ansi6`).
- **Routines**:
  - The scheduler is a block of this layout: under another layout, or with Herdr closed, nothing runs, and the minutes are recorded as missed once it is back.
  - `run()` returns nothing, so a run finds its tab by its unique name "<routine> · HH:MM" and the Routines space by that tab; two manual runs of one routine in one minute share a name.
  - A mod command takes no arguments: the toast stores the run to show in `shared("benni.routines.show")` and runs `benni-routines.open-run`.
  - `-p` runs cannot answer permission prompts: tools the user's settings don't allow are refused. A folder Claude Code doesn't trust yet stops an interactive run on the trust question (it shows under "Needs you").
  - Claude push reaches the phone only through Remote Control, which `claude -p` cannot start: the switch is off in `-p` mode, and even interactive, Claude's PushNotification may skip it when it thinks the person is at the terminal.
  - The interactive summary reads Claude Code's private transcript files (like `claude-workflow`); the `--effort` levels and model aliases come from `claude --help` 2.1.332.
  - Routines run on this computer only (the folder comes from the local folder picker).
- `git-graph` checks the app version to decide whether lists zoom themselves (0.1.12 and later).
- **`claude-workflow` reads Claude Code's private files** (`sessions/`, `projects/`), whose layout can change with any Claude Code release; it was built against 2.1.332. It needs `python3`, and only sees sessions on this computer (remote panes never show the pill). The tab area's place comes from the layout (`sidebar`, `tabs`, `work-body` padding and gap, `panel`) times `settings().zoom`, with overlay sizes given at zoom 1; in a split tab the veil and card cover the whole tab area, not on the Claude pane.
